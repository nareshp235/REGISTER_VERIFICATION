# Register Verification Environment (reg_v.1)

## Overview

reg_v.1 extends the reg_v.0 register verification environment by introducing a simple DMA hardware block.

In reg_v.0, the testbench directly drove the STATUS field through the `hw_status` signal.

In reg_v.1, the STATUS field is generated by actual RTL logic (`dma_core`), creating a complete hardware/software interaction path.

This version demonstrates how software configures hardware through registers and how hardware reports status back through status registers.

---

## Evolution from reg_v.0

### reg_v.0

TB played two roles:

* CPU / Software
* Hardware Status Generator

Architecture:

Software (TB) → reg_block

Hardware Status (TB) → reg_block

---

### reg_v.1

STATUS generation moves into hardware.

Architecture:

Software (TB)
↓
reg_block
↓
dma_core
↓
STATUS
↓
reg_block
↓
Software (TB)

This creates a realistic peripheral architecture.

## Register Map

CTRL_REG

Address: 0x0000_1000

| Bits  | Field    | Access | Reset  |
| ----- | -------- | ------ | ------ |
| 31:16 | Reserved | RO     | 0x0000 |
| 15:8  | MODE     | RW     | 0x01   |
| 7     | ENABLE   | RW     | 0      |
| 6:0   | STATUS   | RO     | 0x00   |

---

## Configuration Registers

### MODE

Bits: [15:8]

Access: RW

Purpose:

Configures DMA operating mode.

Supported values:

| Value | Meaning         |
| ----- | --------------- |
| 0x00  | Normal Transfer |
| 0xFF  | Error Mode      |

---

### ENABLE

Bit: [7]

Access: RW

Purpose:

Starts DMA operation.

| Value | Meaning      |
| ----- | ------------ |
| 0     | DMA Disabled |
| 1     | DMA Enabled  |

---

## Status Register

STATUS[6:0]

Access: RO

Generated by dma_core.

| Bit | Name     | Description              |
| --- | -------- | ------------------------ |
| 0   | BUSY     | DMA transfer in progress |
| 1   | DONE     | DMA transfer completed   |
| 2   | ERROR    | DMA transfer failed      |
| 6:3 | Reserved | Reserved                 |

---

## DMA Core Behavior

### Reset State

BUSY  = 0

DONE  = 0

ERROR = 0

---

### Normal Transfer

Software writes:

MODE = 0x00

ENABLE = 1

DMA sequence:

IDLE
↓
BUSY
↓ (5 clock cycles)
DONE

Final Status:

STATUS = 0b0000010

---

### Error Transfer

Software writes:

MODE = 0xFF

ENABLE = 1

DMA sequence:

IDLE
↓
BUSY
↓ (5 clock cycles)
ERROR

Final Status:

STATUS = 0b0000100

## Learning Objectives

reg_v.1 introduces:

* Register-to-Hardware connectivity
* Hardware-to-Register status reporting
* Simple finite state machines
* Software polling model
* DMA-style control/status architecture
* End-to-end hardware/software interaction

These concepts form the basis of UART, SPI, GPIO, Timer, DMA, and Interrupt Controller peripherals used in real SoCs.
